# Domain documentation

This template uses the single-context layout. Read `CONTEXT.md` before planning
or naming issues and consult relevant records under `docs/adr/` before changing
an established decision. Missing ADRs are not errors; create them lazily when a
grilling or domain-modeling session resolves a consequential choice.

Use the glossary's exact terms in issue titles, specs, branch descriptions, and
tests. Surface conflicts with an existing ADR rather than silently replacing it.
